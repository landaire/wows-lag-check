How this works

Gap
Time between two consecutive ServerTick packets (the game's "your client got an update" signal, normally fired ~7 times per second). A gap of 500 ms or more is flagged as a spike.
Peak ping
Highest ping value reported by the client (via PlayerNetStats, ~10 Hz) during the gap window plus a 2-second tail to catch the RTT estimate catching up after the stall ends.
Server-only stall
The client was alive throughout: local-only packets (Camera, GunMarker, PlayerNetStats; ~30 Hz combined) kept landing in the replay while server-driven packets stopped. The server (or the network between you and it) was the problem.
Client+server stall
Even the client's local packets dried up inside the gap. Either the client froze for unrelated reasons, or a long server stall blocked the network thread to the point the client couldn't tick. Classified by client packet rate <= 5 Hz inside the gap.
Battle time
Replay clock minus the moment the match starts. Exact when entity defs load and the BattleLogic.battleStage signal is captured; otherwise approximated as replay clock minus 30 s (the standard pre-battle countdown for Random / Co-op / Ranked / Brawl; Operations and Scenarios differ), and the column header is annotated with "(approx)".
